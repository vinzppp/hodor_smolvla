     holes:
       H1 Ceiling on the outcome the hypothesis is about (fatal as stated). If the cover-binding tracker is right, every channel reduces to "the target container is at (x, y)". RoboMME already shows that a single text coordinate gets pi0.5 to 99% on VideoUnmaskSwap. With a good graph, channels 1-3 can all saturate on the Video tasks, so "differ substantially" fails or reflects only ButtonUnmaskSwap. Saturation and a real "no difference" result would look the same unless graph quality is varied on purpose.
       H2 Channel is confounded with content (fatal as stated). Arm 1 carries a 2D marker and a label. Arm 2 carries whatever the serializer writes. Arm 3 carries the DINOv2 feature, 3D centroid and box. A gap between arms then can't be attributed to the channel. Fix: send identical fields (id, label, image-plane position, hidden flag, optionally the 3D centroid as numbers) through all three, and run "features" as a separate factor.
       H3 Trainable capacity differs (risk). The SmolVLA defaults are train_expert_only=True and freeze_vision_encoder=True. Arm 3 adds a projector plus LoRA. Unless every arm gets the same LoRA, arm 3 wins or loses on capacity, not channel.
       H4 Graph accuracy, not channel, may set the result (risk). Swap containers are probably near-identical, so DINOv2 features can't re-identify them after a swap. Binding then depends on frame-to-frame tracking through the swap motion, which Dual-Stream reports as unsolved for implicit memory. Every arm inherits the same graph errors. Graph accuracy per task has to be reported, plus an oracle-graph arm.
       H5 SmolVLA input limits (risk). The default tokenizer_max_length is 48 (configuration_smolvla.py), so a serialized graph is truncated unless this is raised, and the raised length was never seen in pretraining. Images go to 64 visual tokens per frame (pixel shuffle) from 256x256 padded to 512, so small markers or labels may not survive. Decide whether markers go on the front camera, the wrist camera or both.
       H6 LeRobot wrapper drops history and caps length (risk, easy fix). RoboMMEGymEnv._convert_obs keeps only front_rgb_list[-1]. The step-0 video in Video* tasks therefore never reaches the policy, and the graph builder must read the raw obs list at reset. env.episode_length defaults to 300 while VideoUnmaskSwap and ButtonUnmaskSwap average 348 and 400 steps (the paper caps at 1300). Without overriding it, Swap runs get truncated and the comparison breaks.
       H7 3D centroids need depth and camera parameters (feasibility risk). The lerobot/robomme dataset has RGB (front, wrist), state, actions and subgoal strings only. Building training-time graphs means replaying the 400 demos in ManiSkill with depth rendering, or using privileged sim poses, which then counts as an oracle.
       H8 Floor and variance (evaluation risk). No SmolVLA numbers exist on RoboMME, and pi0.5 (much larger) gets only 6.67 on ButtonUnmaskSwap with no memory. If SmolVLA can't execute 400-step swaps, every arm stays low. With 50 test episodes per task, a 95% CI is about +/-14 pp near 50%, so "substantial" differences need several seeds (RoboMME uses 9 runs per model).
       H9 Generalization of "which channel to use for VLAs" (risk). One 450M backbone, 4 tasks and 400 demos can't support a recommendation for VLAs in general. VLA-OS already reports a visual-over-language trend at other scales, so a contrary SmolVLA result could be backbone-specific.

Positioning notes
  1. State the contribution as a controlled channel ablation: same per-object content, same trainable parameters, same backbone, measured across graph-quality levels. Do not frame it as an object-memory method. Ledger, ECoMEM and SimpleARM already beat pi0.5 baselines on RoboMME with explicit memory.
  2. The robust result to aim for is "channel X degrades least as graph error grows". "Channel X wins at oracle quality" is likely to be saturated on the Video tasks (GroundSG+Oracle text gets 99% on VideoUnmaskSwap).
  3. Most likely to fail: the token channel (3). A projector trained from scratch on 400 demos, feeding a frozen-pretrained VLM, can be ignored by the action expert. Probe it with a counterfactual-graph test (move the hidden target in the graph and check whether actions follow).
  4. Second most likely to fail: the visual channel on hidden objects. At 64 visual tokens per 512-padded frame, a small marker on a closed container may not survive. Test marker size and frozen versus LoRA vision early.
  5. Required baselines: no graph; dataset grounded_subgoal text (RoboMME's GroundSG-oracle analogue); oracle sim graph through each channel; a short frame-history baseline (no graph), so the graph is compared against plain history; and cited pi0.5 numbers from RoboMME for scale.
  6. Report graph accuracy per task, especially identity accuracy after a swap, separately from policy success. ButtonUnmaskSwap is where the cue is brief and differences should show.
  7. Fix the LeRobot wrapper first: read the raw front_rgb_list at reset for the Video tasks and set episode_length to at least 1300. Use several seeds, since 50 episodes give about +/-14 pp per task.
